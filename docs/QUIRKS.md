# Quirks

Traps that cost someone a debugging session. Rules and commands live in `AGENTS.md`; settled calls in `DECISIONS.md`.

## CSS and rendering

- `@property` changes computed-value representation (alpha `10%` → `0.1`, `0.625rem` → `10px`). Token tests must normalise through a real CSS property, and `initial-value` must be computationally independent — no `var()`, no `rem`.
- `light-dark()` resolves at the declaring element's `color-scheme`, so `.dark` must be on `<html>`.
- `@starting-style { transform: scale(0.96) }` corrupts a `getBoundingClientRect` taken right after `showPopover()`.
- `height: 0` cannot collapse a `border-box` element that carries padding, and a zero-height flex child still occupies its slot in the parent's `gap`. Both remainders are released in one frame when React unmounts the node, outside any animation. Disclosure spacing therefore goes on an **inner wrapper** — `ui/accordion` does this, `ui/collapsible`'s demos had to be fixed to match (ISSUES E2).
- A border under a `mask-image`, filter or transform still reports full `border-width` in `getComputedStyle` while painting nothing. Assert pixels for anything those can suppress.
- Same family: with `outline-style: none`, computed `outline-width` is 0 per spec — but newer Chrome reports the cascade's specified width anyway, so a width-only assertion can pass while nothing paints (ISSUES G11 rode this for weeks). Assert the style alongside the width.
- `styles/globals.css` has **no `p`/margin reset**. A bare `<p>` keeps its UA `margin-block: 1em`, and flex items don't collapse margins, so it *adds* to the parent's `gap`. Set `margin: 0` on prose you add.
- `styles/van.css` must never be imported by `site/main.jsx` — it is a *consumer's* theme and at equal specificity wins on source order, re-theming the site and pinning `--density-scale`. There is a comment saying so; leave it.
- `container-type: inline-size` zeroes the element's intrinsic contribution, so a parent's `min-inline-size: fit-content` cannot see through it — `ui/scroll-area`'s content stayed 576px around a 640px table and its ResizeObserver never fired (ISSUES C13). Put the container on an element sized by layout, not by its content.
- **`ui/scroll-area`'s viewport sets `overscroll-behavior: contain`**, which also stops scroll chaining from a container that cannot scroll on that axis. A `DataTableScroller` with no height limit never overflows vertically, so the wheel died over the table while the page scrolled beside it. The console chains the vertical axis back with `overscroll-behavior-y: auto` on `.ck-table-wrap .scroll-area-viewport`; the kit still contains both axes.
- Hit-testing cannot show one cell's text painting over the next: a later `position: relative` sibling hit-tests on top of the earlier one's overflow, so `elementFromPoint` answers with the neighbour either way. Sample pixels instead (ISSUES C12, the C5 technique).

## Tests

- `resetPage()` pins `colorScheme: "light"`. Keep it pinned: the site seeds its theme from `prefers-color-scheme`, so resetting to `null` makes every suite depend on whether the developer's OS is in dark mode.
- **A computed colour read right after `classList.add("dark")` is the transition's start value, not the new scheme.** Every kit control transitions `background-color` and `color` over `--motion-fast`, and children (SVG strokes, badge text) inherit the in-flight `color`, so a `getComputedStyle` in the same tick reads the light paint on every button while `<header>` and `<div>` siblings, which have no transition, already read dark. This looked exactly like Chrome failing to re-resolve `light-dark()` on form controls; a forced reflow "fixed" it only because `display: none` cancels transitions. Before asserting on a scheme flip, wait until `document.getAnimations()` holds no `CSSTransition` (`tests/showcase-console.test.mjs`).
- Assert motion in pixels, never animation objects. To catch a mid-frame, set `--motion-scale` high (25 works) and screenshot — Playwright does capture view-transition pseudos.
- A high `--motion-scale` buys a wide window, not a known clock. `mode-toggle` sampled its swing at 700ms and 2300ms into a scaled animation and once read the zero *crossing* between the two extremes as a stalled lamp (-0.006deg). Sample every frame inside the page and take the peaks out of the series, or wait for the state you mean.
- For motion QA emulate `no-preference`. Don't act on a missing-animation report before checking this.
- `dispatchEvent` on a modal `<dialog>` fires natively but React's delegated handlers never run. Use real Playwright pointer input. For a flick, declare its timing through CDP `Input.dispatchMouseEvent` `timestamp`s (`timedDrag` in `tests/drawer.test.mjs`): `page.mouse` stamps wall-clock time, so the px/ms `use-swipe` measures tracks machine load, and a 16–29ms pass window flakes on a shared runner.
- A page must have exactly one `h2` — its title. Several suites click a bare `locator("h2")` as an outside-click target. Site styles use child combinators (`.pg-section > h3`), so page structure matters.
- Concurrent suites each need their own `VANILLIN_TEST_PORT`; the runner pins one port with `--strictPort`. CPU contention manufactures flakes — see ISSUES G before believing a timing failure, and re-run the file in isolation.
- **`forced-colors` CSS is correct.** Those failures were input-modality leakage between test files, fixed by `resetPage()` in `tests/run.mjs`. Don't re-fix the CSS.
- **`GITHUB_ACTIONS` used to move the dev server under `/vanillin/`.** `vite.config.js` keys `base` on that variable for Pages, and until it was scoped to `command === "build"` the *dev* server inherited it on a runner. Every root-absolute URL in the suite then 404'd — `/@id/react` and `/@fs/…` (slider), `/showcase/panels/fixture.html` (the whole showcase-panels suite), and `${baseUrl}/#button`, which redirected to `/vanillin/` and dropped the hash, so `docs-shell` counted the home page's `h2`s. Four failures, one variable, and none of them reproducible locally. If a suite fails only in CI, check the base first: `curl -o /dev/null -w '%{http_code}' localhost:5199/@id/react`.
- **A leaked dev server silently tests the previous config.** `--strictPort` makes a second vite exit rather than pick another port, and `waitForServer` cannot tell whose server answered — so the run passes against a stranger. `tests/run.mjs` now refuses to start when the port is busy, and spawns vite as `node node_modules/vite/bin/vite.js` rather than through `npx`, because `vite.kill()` only reached the `npx` wrapper and left the real server holding the port. This is the mechanism behind "passed an hour later on identical code" (ISSUES G5, G8).
- **`locator.boundingBox()` hangs on an element with an infinite animation** — Playwright's actionability wait never sees it settle and times out at 30s. Read geometry with `evaluate((el) => el.getBoundingClientRect())`. And `page.screenshot({ clip })` takes **viewport** coordinates: scroll the target into view first and do not add `window.scrollY` (task 92).
- **`getBoundingClientRect().width` ignores `translateX`.** An indicator parked at `translateX(-100%)` reports its full width while painting nothing, so `width > 0` cannot detect an off-track element — assert overlap with the container's rect, and for motion sample the offset over frames. That is how `ui/progress`'s indeterminate bar stayed invisible under a passing-looking assertion (task 92).
- **`tests/badge.test.mjs`'s last chip test navigates to `#combobox`**, so a test appended after it runs on the wrong page and times out on its locator. Insert badge tests before the chip block.
- **Anything a React effect or an observer sets is not on the element when `click()` resolves.** Wait for it, never sample it. `data-trend` (`ui/live-value`) arrives in a post-commit effect and clears again on `animationend` — a 600ms window at the default scale — and CI read both edges of it (`got null`, then `got "up"` after the failed test left its flash behind). `ui/select`'s scroll buttons come from an IntersectionObserver (ISSUES G7). Widening the window with a subtree-local `--motion-medium` makes the *reading* safe; it does not remove the need to wait.
- **A colour probe resolves `light-dark()` at the probe's own scheme.** `.ck-topbar` forces `color-scheme: dark`, so `var(--ck-orange)` read from a span appended to `.ck-console` is the light arm while the order button inside the chrome paints the dark one — the two strings differ and the comparison fails on correct CSS. Append the probe inside the element you are comparing against (`consoleColour(token, host)` in `tests/showcase-console.test.mjs`).
- **`lib/use-ticker`'s count is page-global per interval and never resets.** Anything that derives a figure from the raw tick reads a value that depends on how long the page has been open: the taskbar's running bars sat at 99% by the time their suite ran, ten minutes into a full run. Record the tick a panel opened on and count from there.

## Shell and git

- **zsh does not word-split unquoted `$var`.** A newline-separated file list in `git diff … -- $files` becomes one bogus pathspec matching nothing, and an empty diff reads as "no differences" — it fails silently and reassuringly. Use `git diff -z --name-only … | xargs -0 git diff …`.
- `merge.conflictStyle` is `zdiff3`, so conflicts carry a third section (`||||||| <sha>`) holding the common ancestor. It is context, **never a resolution** — in lazygit it is a selectable hunk, and picking it reverts the region to the ancestor.
- `git branch -a` lists branches already deleted on the remote until `git remote prune origin`. Confirm against GitHub before reporting branch state.
- `site/dist/` is stale untracked build output and pollutes `grep -r`. The Pages workflow builds its own copy in CI.
- Visual QA: `npm run dev` (:5173), hash routes are `#<slug>`, dark mode is the `.pg-theme-toggle` button.
