# AGENTS.md

Orientation for coding agents. Everything here is what you cannot learn from a single file. `README.md` covers the consumer story and component API conventions; `docs/HANDOFF.md` carries current state, the full convention list, and the gotchas. Don't duplicate either here.

## Commands

```sh
npm run dev                 # docs site, :5173 — visual QA only
npm test                    # full suite (needs Google Chrome installed)
node tests/run.mjs drawer   # subset: substring match on test filenames
npm run build               # vite build → site/dist
npm run contracts           # regenerate .van.json manifests + registry.json
npm run theme               # van.config.json → styles/van.css
npm run theme:defaults      # van.defaults.json → styles/defaults.css
```

No linter is configured.

- **`npm test` exits 0 even when tests fail.** The trailing `N/M passed` is the only signal; piping through `tail` discards the `FAIL` lines. Use `npm test > out.txt 2>&1`, then grep `^FAIL`.
- **Run `npm run contracts` after any `ui/` edit** or conformance fails on stale hashes.

## Layers

Dependency order. `ui/` imports from `lib/` and from other `ui/`; nothing imports from `site/`.

| Layer | Role |
|---|---|
| `styles/globals.css` | every design token, light + dark — the only source of colour, spacing, radius, motion |
| `lib/` | framework-free primitives; this is where Radix/Floating-UI is replaced (`use-dismissable-layer`, `use-focus-trap`, `use-roving-focus`, `use-anchor-position`, `use-presence`, `use-safe-triangle`) |
| `ui/<slug>/` | `<slug>.jsx` + `<slug>.css` + generated `.van.json` |
| `site/` | docs site (Vite SPA, hash routes `#<slug>`) — the demo page *is* the docs page |

Overlays are native `<dialog>`/popover. `ui/dialog` and `ui/popover` are pattern-setters that later components re-export from rather than copy — `ui/alert-dialog` and `ui/context-menu` are thin re-exports, which is why their CSS block classes are allowlisted in the conformance suite.

## Three registries

Easy to confuse; they answer different questions.

| File | Generated by | Purpose |
|---|---|---|
| `site/registry.js` | hand-written | docs nav + `lazy()` page import per component |
| `registry.json` | `scripts/build-registry.mjs` | what the CLI copies — `files`, `requires`, `lib` |
| `ui/<slug>/.van.json` | `scripts/manifest.mjs` | per-copy provenance + file hashes, so `van diff` tells kit changes from consumer edits |

Both generated files derive `requires` from the same `deriveRequires()` in `scripts/manifest.mjs`, so the upstream graph and consumer copies cannot disagree.

Theming is likewise generated, never hand-edited: `scripts/build-theme.mjs` + `scripts/config-schema.mjs` turn `van.config.json` → `styles/van.css` (a consumer's overrides) and `van.defaults.json` → `styles/defaults.css` (the kit's own theme).

`bin/van.mjs` is Node stdlib only — `init`/`add`/`diff`/`build`/`list`. Path safety is an allowlist: slugs are looked up in `registry.json`, so `../evil` fails as "unknown component".

## Tests

The extension picks the runner:

- `tests/<slug>.test.mjs` — browser suite, default-exports `async ({ page, baseUrl, repoRoot, test, eq, near })`.
- `tests/*.unit.mjs` — pure Node, run as child processes first. `conformance.unit.mjs` enforces the conventions statically; new exceptions go in its allowlists **with a reason**, never by weakening a rule.

`tests/run.mjs` self-hosts vite on :5199 (`VANILLIN_TEST_PORT`) and drives locally installed Chrome via `playwright-core`. **All suites share one page**, so state leaks downhill in alphabetical order — read that file's comments before chasing a failure that only appears in a full run.

Implementation first, then tests, one green run — never test-driven. Assert rendered pixels or computed values, never animation objects: a `mask-image` implementation once produced a flawless `getKeyframes()` and painted nothing.

## Docs map — read the one matching the work

| Doing | Read |
|---|---|
| anything non-trivial | `docs/HANDOFF.md` — state, conventions, **gotchas**, decisions not to re-litigate |
| planning, or a numbered task | `docs/TODO/README.md`, then `docs/TODO/taskNN-*.md` |
| asking why a past task went that way | `docs/TODO/LOG.md` — append here when a task lands, not to the TODO README |
| touching bugs | `docs/ISSUES.md` — triage inbox; re-verify line numbers, they drift |

## Hard rules

- **Zero runtime dependencies but React.** Everything in `devDependencies` serves the docs site or tests. A devDependency imported from a docs page *is* a runtime dependency — this has broken the build before.
- **No commits on `main`** — hooks enforce it. Branch `<type>/<kebab>` first. `git merge`/`rebase`/`reset --hard` are denied in settings (`git merge-base` and `merge-tree` trip the same rule — use `git diff a...b` and `git rev-list --count a..b`). Merges are the user's to run; you cherry-pick.
- Stage diffs and stop. No AI attribution in commits — no `Co-Authored-By`, no trailers.
- The ~500-net-line branch-size hook is advisory. Never split or restructure work because of it.
- Every task ships its prose in the same PR as its code.
- Pushing `main` deploys `site/dist` to GitHub Pages. **The workflow does not run tests**, so a red suite still deploys.
